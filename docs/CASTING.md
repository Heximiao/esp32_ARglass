# 浏览器投屏

电脑浏览器选择屏幕/窗口/标签页，通过本地 Wi-Fi 向 ESP32-S3 发送画面。
**不采集、不发送音频。** 当前发送端建议使用桌面 Chrome 或 Edge。
网页由 ESP32 自身提供，不需要电脑安装发送程序，也不依赖外部网站。

## 推荐：使用电脑投屏助手

本版已去掉配对码。电脑助手位于旁边的 `../arglass_assistant`，成品为 `dist/ARGlassAssistant.exe`。
先上传本版固件，眼镜连接 Wi-Fi 并进入开始投屏等待页；电脑双击 EXE，输入眼镜 LAN IP 或点击查找，连接后选择共享画面。
这条路径无需导入设备证书，也不依赖代理的 `.local` 解析。助手页面只监听本机回环地址，向眼镜 IP 的 80 端口 `/ws` 原样转发。
原 HTTPS 浏览器投屏方式保留，仍需信任项目证书；以下证书设置仅适用于直接打开眼镜 HTTPS 页面。

## 第一次使用

1. 在项目目录运行 `pio run --target upload`，上传本版固件和新分区表。
   普通 PlatformIO Upload 会包含分区表。不要只手动烧录旧地址下的单个固件文件。
   原图片的 LittleFS 偏移、大小不变，无需重新上传图片或擦除整个 Flash。
2. 眼镜首页进入“投屏 → 连接 Wi-Fi”，等待扫描结束，选择电脑所在的 **2.4 GHz** Wi-Fi（也可选电脑开启的 2.4 GHz 热点）。
3. 用五维摇杆操作密码键盘，选择 `JOIN` 连接；开放网络直接连接。成功后配置自动保存。
4. 中键回投屏菜单，连接方式选 Wi-Fi，选“开始投屏”。电脑保持在同一局域网，无需先连接眼镜热点。
5. 首次使用，按照下文手动信任项目中的 `certs/ar-glass-root.crt`。
6. 电脑打开 **https://ar-glass.local/**，点击连接设备，再点击“选择画面并开始投屏”。本版不再使用配对码。

设备热点仍可选：将“连接方式”切到 `HOTSPOT` 后开始投屏，电脑连接眼镜显示的 SSID/密码，
首次说明页为 `http://192.168.4.1/`，投屏页为 `https://192.168.4.1/`。热点密码每次启动随机生成。

眼镜中键短按停止接收并回投屏菜单；等待/显示页面长按也回投屏菜单，再长按返回首页。
浏览器点击“停止”或浏览器自带的“停止共享”，会停止所有采集轨道。
电脑明确停止或连接关闭后，眼镜恢复等待页面；短暂断帧保留最后画面，连续 10 秒没有完整帧时才回等待页。
超时判断防止网络线程的新时间戳比主循环时间快而发生无符号减法溢出；首次 FPS 统计完成前显示 `--FPS`。
网络服务保持运行，方便重新连接和配网；重新从眼镜“开始投屏”可重新授权接收。

## 为什么首次需要 HTTPS 设置

`getDisplayMedia()` 要求安全上下文和用户主动授权，普通局域网 HTTP 地址不能直接采集屏幕。
本项目提供 HTTPS 页面和 WSS 长连接；证书只用于 `ar-glass.local` 和 `192.168.4.1`。
**不能假定点过“不安全，继续访问”就一定能取得屏幕捕获权限。**

证书属于这个本地项目，不是公共 CA 签发，所以首次要由用户手动信任。
程序不会自动安装证书、修改系统信任或关闭浏览器安全检查。

Windows Chrome / Edge 的配置步骤：

1. 优先使用项目内 `certs/ar-glass-root.crt`，或从设备 HTTP 设置页下载同一证书。
2. 使用 PowerShell 核验本地项目证书指纹：

   ```powershell
   $cert = [System.Security.Cryptography.X509Certificates.X509Certificate2]::new((Resolve-Path certs/ar-glass-root.crt))
   $cert.GetCertHashString([System.Security.Cryptography.HashAlgorithmName]::SHA256)
   Get-Content certs/fingerprint.txt
   ```

   两者应一致；从设备下载的证书也应和本地项目一致。
3. 双击证书 → 安装证书 → **当前用户** → 将证书放入“受信任的根证书颁发机构”。
   仅对你自己控制的设备和核对过的项目证书进行此操作。
4. 完全关闭并重新打开浏览器，Wi-Fi 模式访问 `https://ar-glass.local/`，热点模式访问 `https://192.168.4.1/`。
   应没有证书名称或信任错误。网页会在无法使用屏幕捕获时显示提示。

Firefox 使用自己的证书信任设置时，需要单独配置；手机浏览器整屏共享不在本版支持范围。
公司管理的电脑可能禁止导入本地 CA 或屏幕共享，需遵循该电脑的管理策略。

项目证书生成方式：

```powershell
python -m pip install cryptography
python tools/generate_cast_tls.py
```

当前工作区已经生成。默认保留现有身份；`--force` 可轮换身份，之后电脑需信任新的根证书。
设备证书有效期一年，根证书十年。CA 签名私钥只存在于生成过程内存中，不会保存；
设备只保留范围受限的服务器私钥。`src/cast/private/` 已加入忽略列表，请勿提交其中内容。
复制项目到新环境时需自行生成凭据；构建脚本在缺少凭据时会提示。

## 连接现有 Wi-Fi

直接在眼镜“投屏 → 连接 Wi-Fi”配网，不依赖电脑先连接眼镜热点。

- 列表按信号强弱排序，相同 SSID 合并，显示最多 24 个网络；长网络名截断显示，进入键盘后标题滚动显示。
- 上下选择网络，中键确认；“刷新列表”重新扫描，“SAVED”行使用已保存的密码重连。
- 键盘上下左右移动，中键输入。`ABC/abc` 切换大小写、`#+=` 切换符号、`SP` 空格、`DEL` 删除、`EYE` 显隐密码、`JOIN` 连接。
- 支持全部可打印 ASCII；普通密码 8–63 位，也支持 64 位十六进制 PSK。默认掩码，退出清空草稿。
- 长按中键返回；连接过程中长按中键取消。扫描/连接异步执行，沿用现有摇杆消抖和方向连发。
- 连接成功取得 IP 后才替换 NVS 中的 SSID/密码；约 20 秒超时，失败不覆盖旧的保存网络，也不自动切热点。
- 支持开放网络和个人密码网络；企业认证/WEP 显示 `N/A`，隐藏 SSID 手工输入不在本版范围。

开机会在后台自动连接最后一次成功保存的 Wi-Fi；失败或断线后约每 30 秒重新尝试，单次连接最多等待 20 秒，首页和摇杆不阻塞。
进入手动配网页面时暂停自动重试；主动选择设备热点后也停止后台重试，避免影响热点信道。
目前保存一组最后成功的网络信息，不是多网络历史列表；开机连接 Wi-Fi 不会自动开始接收投屏。
以后选择“连接方式 → Wi-Fi”再开始投屏，会使用保存的网络；电脑连接同一局域网后打开 **https://ar-glass.local/**。
浏览器的 Wi-Fi 表单仍可使用，是另一个可选入口，连接成功后同样保存。
网页和眼镜显示的投屏设置是同一份，修改后会保存到 NVS。

若 `ar-glass.local` 无法解析，先回设备热点使用 `https://192.168.4.1/`；
需确认电脑允许 mDNS、多播及同网段设备访问，访客网络的客户端隔离可能阻止连接。
直接访问随机分配的路由器 IP 可能产生证书名称错误，因此默认用上述固定名字。

## 局域网 IP 与代理兼容

配网成功页会显示 `LAN IP`；投屏等待页在 Wi-Fi 模式下也显示当前局域网 IP 和 `http://IP` 诊断入口。
显示来自实时 DHCP 地址，不写死 IP，断线或尚未取得地址时显示 `not connected`。
HTTP 页面仍然只提供首次连接说明和公开根证书，不在普通局域网 HTTP 页面采集屏幕。

如果 TUN/Fake-IP 把 `ar-glass.local` 接管，直接访问显示的 `http://IP` 可排除域名解析问题，
但局域网路由仍受电脑代理策略控制。现有设备证书仅包含 `ar-glass.local`、`192.168.4.1`；
不能把任意 DHCP IP 的 `https://IP` 当作已匹配证书的投屏入口。

面向其他用户，免改代理、免导入证书的一种后续方案是提供电脑本地投屏助手：
浏览器打开 `http://localhost` 采集屏幕，助手通过眼镜 IP 转发画面、管理设备连接。
这可消除 `.local` 解析和浏览器访问设备 HTTPS 的依赖，但仍需允许电脑访问本地网络；
固件无法保证绕过所有强制隧道路由、防火墙或网络隔离策略。助手已实现，见旁边的 `../arglass_assistant/README.md`。

## 投屏设置

可在“设置 → 投屏设置”、投屏菜单或浏览器修改：

| 项目 | 值 |
| --- | --- |
| 传输格式 | 连续 JPEG / 原始 RGB565 |
| 目标帧率 | 5、10、15、20、25、30、40、50、自动 |
| JPEG 质量 | 50 / 70 / 90，RGB565 下不参与编码 |
| 画面比例 | 完整显示 / 保持比例裁剪填满 |
| 显示帧率 | 眼镜画面角落显示实际 FPS，可关闭 |

默认 JPEG、30 FPS、质量 70、完整显示。自动模式发送端上限 50 FPS。
**这些是目标上限，不是实测帧率承诺。** 浏览器展示的实际 FPS 来自设备完成刷屏的统计。
屏幕按当前 256×172 可视区显示，左右黑边及字体原始像素布局不变。

## 实现与性能

- WSS/TCP 长连接，关闭 Nagle 延迟，最多两帧在发送中；收到完整帧后确认，发送端按反馈同步配置。
- 浏览器负责缩放和裁剪。JPEG 使用浏览器原生编码；RGB565 由 Canvas 像素转换为小端数据。
- 输入双缓冲、JPEG 解码输出缓冲及解码器放在 PSRAM，网络接收和主循环解码/显示可重叠。
- 浏览器可能拆分大 WebSocket 消息，接收端支持 BINARY / CONTINUATION 分片重组。
- 待显示队列优先取新帧并丢弃旧帧，不堆积长延迟。
- 投屏画面与 LVGL 共用同一主循环独占 SPI；投屏时抑制 LVGL 刷新，退出后完整重绘菜单。
- Wi-Fi 关闭省电以降低接收延迟；屏幕仍为 40 MHz SPI，没有默认提高到未经验证的频率。
- 网页静态资源 gzip 编译进固件；不占图片文件系统、不下载远端脚本。
- TLS 占用内部 RAM，实际网络、TLS 内存余量和连续运行稳定性需实机确认。

### 二进制帧协议

每个 WebSocket 二进制消息：20 字节头 + 一帧负载。字段均为小端：

| 偏移 | 内容 |
| --- | --- |
| 0..3 | ASCII `ARS1` |
| 4 | 格式 1=JPEG，2=RGB565_LE |
| 5 | 保留，必须为 0 |
| 6..7 | 宽，必须等于配置可视区宽度 |
| 8..9 | 高，必须等于配置可视区高度 |
| 10..11 | 头长度，必须为 20 |
| 12..15 | 帧序号 |
| 16..19 | 负载长度 |

最大负载 96 KiB；RGB565 必须恰好宽×高×2；JPEG 必须是相同尺寸的 baseline JPEG。
接收后还会检查尺寸、格式、长度、保留字段及 JPEG 标识，解码失败不会刷新屏幕。
设备不再使用配对码；须在眼镜上选择开始投屏，HTTPS/WSS 与助手使用的 HTTP/WS 共用单发送端限制。

## 分区与验证

投屏前原固件约 2.96 MiB，新固件约 **3.57 MiB**，原 3.19 MiB 单槽放不下。
按用户要求合并两个应用槽：`app0` 改为 factory，起始 `0x10000`、大小 `0x660000`（6.375 MiB）。
NVS 保持 `0x9000` / `0x5000`，图片分区保持 `0x670000` / `0x190000`，末尾仍为 8 MiB。
原 otadata 区保留但 factory 启动不依赖它；当前布局不提供双槽 OTA。

已执行固件编译、浏览器本机 HTTPS/WebSocket 测试、JPEG/RGB565 格式切换、
RGB565 字节顺序、5 FPS 限速、两帧背压、停止/重新开始、设备退出后释放采集轨道、响应式布局检查。
浏览器测试使用合成视频和本机协议测试端，不代表真实 ESP32 上的吞吐和帧率。
**尚未烧录实机，也未验证真实无线投屏帧率、HTTPS 内存峰值和长时间稳定性。**

主要文件：`src/cast/CastService.*` 接收/解码/网络状态，`CastServer.*` HTTPS/WSS，
`WifiScan.*` 异步网络扫描，`src/ui/pages/WifiPage.*` 眼镜配网，
`src/ui/PasswordKeyboard.*` 摇杆密码键盘，`CastTypes.h` 协议，`web/cast/` 浏览器发送端，`src/ui/pages/CastSettingsPage.*` 投屏设置。

测试命令（电脑安装 Node、Playwright 和 Chrome 后）：

```powershell
node --check web/cast/app.js
node test/browser_cast.test.cjs
```

### 新配网功能实机检查

编译通过不代表已通过无线实测。烧录后依次检查：扫描、长 SSID/中文 SSID、大小写/特殊符号密码、
开放网络、错误密码与 20 秒超时、连接中取消、成功后重启重连，以及同网络网页投屏。
确认输错新密码后原 SAVED 网络仍能重连，方向连发不会触发重复中键输入。

### 断帧闪回等待页修复

网络线程可以在主循环记录 `now` 后更新接收时间。旧代码的无符号 `now - lastReceive` 会在这时溢出，
把新帧误判成超时，并清零 FPS、恢复 LVGL 等待页。现在重新采样时间并将“接收时间略新于快照”视作零间隔。
`StreamTiming.h` 包含编译期回归检查，覆盖异步快照、短暂停顿、真实超时及 `millis()` 回绕。
FPS 的采样时间改用刷屏完成时刻；首个有效统计窗口形成前显示 `--FPS`。
本修复仅需更新固件，投屏助手 EXE 无需更换；无线实机效果需重新烧录后确认。
